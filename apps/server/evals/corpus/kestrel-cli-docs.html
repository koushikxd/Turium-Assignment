Kestrel CLI: configuration reference

This page describes every way to configure the kestrel command line tool: the configuration file, environment variables and flags. When the same setting is given in more than one place, flags win over environment variables, and environment variables win over the file.

Configuration file

kestrel reads a TOML file from the path in the KESTREL_CONFIG variable, or from ~/.config/kestrel/config.toml if that variable is not set. A missing file is not an error. An unreadable or invalid file is, and kestrel exits before doing anything else. 

[default]
region = "eu-west"
output = "table"

[profile.staging]
endpoint = "https://staging.kestrel.example"

Profiles are selected with the --profile flag. Settings in a profile override the default section, key by key.

Authentication

kestrel authenticates with an API token. Set it in the KESTREL_TOKEN environment variable or run kestrel login, which stores it in the operating system keychain. Tokens in the configuration file are deliberately not supported, because config files end up in dotfile repositories. A token created in the web console is valid for 90 days; kestrel warns on every command during the last week before it expires.

Output

The output setting takes table, json or yaml. Use json in scripts: the table layout may change between minor versions, but the JSON shape is covered by the compatibility policy and only changes in a major release. The --quiet flag suppresses everything except errors, which is handy in cron jobs.

Networking

kestrel respects the standard HTTPS_PROXY and NO_PROXY variables. Requests time out after 30 seconds by default; change this with --timeout, which takes a duration such as 90s or 2m. Failed requests are retried three times with exponential backoff, but only for idempotent operations. A create or a delete is never retried automatically, so a timeout on one of those means you should check the result with kestrel get before trying again.

Exit codes

kestrel exits with 0 on success and 1 for a generic failure. Exit code 2 means the command line itself was invalid, such as an unknown flag. Exit code 3 means authentication failed or the token has expired. Exit code 4 means the requested resource does not exist. Exit code 75 means a temporary failure, such as a rate limit or a timeout, where running the same command again later may succeed. Scripts should retry only on 75.

Debugging

Set KESTREL_LOG=debug to print every HTTP request and response to standard error, with the token masked. Add --dry-run to any command that changes something to see the request it would send without sending it.
